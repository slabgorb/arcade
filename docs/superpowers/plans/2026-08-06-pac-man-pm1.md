# Pac-Man (pm1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a playable, AI-authentic arcade Pac-Man (1980 Namco, Z80) as the ninth cabinet, with the fleet's fidelity gate installed before any constant is written.

**Architecture:** A pure deterministic `src/core/` simulation (maze, actors, ghost AI, mode/level tables) driven by a thin `src/shell/` (Canvas 2D render, input, fixed-60 Hz timebase), copied in shape from `plugins/centipede/`. Every fidelity constant cites `docs/rom-study/` and is verified by a ported `check-citations.mjs` gate.

**Tech Stack:** TypeScript, Vite (one config factory), Vitest (one project per app), `node:test` orchestrator suite, Canvas 2D, `@shared/*` in-tree modules. Node ≥ 22.18.

## Global Constraints

- **Node ≥ 22.18** — `scripts/` import `.ts` directly via Node type-stripping.
- **Core is pure & sim-clock-free** — nothing in `src/core/` may touch a browser global, wall clock, `Math.random`, timers, or import shell code. Enforced by `purity.test.ts`.
- **ROM always wins** — on any conflict between the Pac-Man Dossier and a playtest feel, the Dossier governs. Do not offer ROM-vs-shipped as a choice.
- **GPL firewall** — `shaunlebron/pacman` is GPL v3, a **read-only oracle**. Never copy a line of its code, structure, or data tables. MAME is the tiebreaker.
- **Every fidelity constant carries a citation** — `pm1-dossier §X` / `brief.md:N`, machine-verified. A number without a citation fails the gate.
- **Frightened-mode randomness is deterministic** — draw from `@shared/rng` seeded per game; never ambient randomness.
- **Four files + three registrations** to add the game; regenerate the registry, never hand-edit `src/host/registry.ts`.
- **Logical backbuffer, integer scale** — render into a fixed 224×288 logical canvas, blit integer-scaled to the visible canvas (the centipede AC-2 crisp-pixel rule).

### Tasks 4–8: gameplay subsystems (separate plans, authored against the transcribed dossier)

Per the writing-plans decomposition rule, each subsystem below is an independent, testable deliverable whose numeric oracles are the `pm1-dossier` sections written in Task 2. Each gets its own plan (or sprint story) authored **after** Task 2 exists, so the test expectations are transcribed, not invented. Interfaces are fixed here so the tasks compose:

- **Task 4 — Pac-Man movement.** `src/core/pacman.ts`, `src/core/actor.ts`. Produces `stepPacman(state, input): void`, `Actor` (pixel pos, dir, the dossier **speed-pattern** table `speedPattern(pct): boolean[]`), cornering + input-latch, eat-pause (1 frame/dot, 3/energizer). Cites `§Speeds`, `§Movement`.
- **Task 5 — Ghost kinematics + house release.** `src/core/ghost.ts`, `src/core/house.ts`. Produces `stepGhost(ghost, target, state)`, tile-centre turn selection (no reverse except on mode signal), `releaseFromHouse(state)` (global + per-ghost dot counters). Blinky direct-chase first. Cites `§Ghost movement`, `§Ghost house`.
- **Task 6 — Targeting (the four personalities).** `src/core/targeting.ts`. Produces `targetTile(ghostId, state): Tile` for Blinky/Pinky/Inky/Clyde, including the Pinky up-direction overflow quirk and Clyde's 8-tile flip. Tested against the dossier's documented example diagrams. Cites `§Ghost AI`.
- **Task 7 — Mode engine + Cruise Elroy.** `src/core/mode.ts`. Produces `stepMode(state): ModeSignal` (scatter/chase per-level timer table, frightened entry/decay/flash, the reverse-on-mode-change signal), Elroy 1/2 thresholds bumping Blinky's speed. Frightened turns via `@shared/rng`. Cites `§Modes`, `§Cruise Elroy`.
- **Task 8 — Level table + round lifecycle.** `src/core/level.ts`, `src/core/game.ts`, `src/core/events.ts`. Produces `LEVELS[]` (speeds, frightened seconds/flashes, fruit type/points, Elroy thresholds — one cited column each), fruit spawn at 70/170 dots, ghost-eaten chain 200/400/800/1600, death/win state machine, lives, extra life at 10 000, high-score entry via `@shared/name-entry`. Cites `§Level table`, `§Scoring`.

Each of Tasks 4–8 follows the same TDD rhythm: dossier-cited failing test → run red → minimal core impl → run green → commit; the `citations` and `purity` gates from Task 2 run on every commit.

## Self-Review

- **Spec coverage:** every §-section of the design maps to a task — placement/registrations→T1, ground-truth+gate→T2, maze→T3, core modules→T3–T8, testing→gates in T2 + per-task TDD. Deferred items (sound, cutscenes, kill-screen, attract) are explicitly out.
- **Placeholder scan:** numeric oracles are deliberately sourced to `pm1-dossier §X` (Task 2's deliverable) rather than fabricated — the correct provenance rule for a fidelity repo, not a placeholder.
- **Type consistency:** `Actor`, `Tile`, `TileKind`, `targetTile`, `stepGhost`, `stepMode`, `LEVELS` are named identically across the interface blocks that produce and consume them.
