# Pac-Man (pm1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a playable, AI-authentic arcade Pac-Man (1980 Namco, Z80) as the ninth cabinet, with the fleet's fidelity gate installed before any constant is written.

**Architecture:** A pure deterministic `src/core/` simulation (maze, actors, ghost AI, mode/level tables) driven by a thin `src/shell/` (Canvas 2D render, input, fixed-60 Hz timebase), copied in shape from `plugins/centipede/`. Every fidelity constant cites `docs/rom-study/` and is verified by a ported `check-citations.mjs` gate.

**Tech Stack:** TypeScript, Vite (one config factory), Vitest (one project per app), `node:test` orchestrator suite, Canvas 2D, `@shared/*` in-tree modules. Node ≥ 22.18.

## Global Constraints

- **Node ≥ 22.18** — `scripts/` import `.ts` directly via Node type-stripping.
- **Core is pure & sim-clock-free** — nothing in `src/core/` may touch a browser global, wall clock, `Math.random`, timers, or import shell code. Enforced by `purity.test.ts`.
- **ROM always wins** — the source of record is the vendored Z80 disassembly `plugins/pac-man/reference/source/pacman.asm` (provenance `reference/PROVENANCE.md`). On any conflict between it and a playtest feel, the ROM governs. The Pac-Man Dossier is the behavioral **decoder** (what routines do, decoded values), not the byte-level truth. Do not offer ROM-vs-shipped as a choice.
- **GPL firewall** — `shaunlebron/pacman` is GPL v3, a **read-only oracle**. Never copy a line of its code, structure, or data tables. MAME is the tiebreaker.
- **Every fidelity constant carries a citation** — a `claims/*.json` entry `{symbol, value, source:'pacman.asm', addr, meaning}` **byte-verified against the vendored `pacman.asm`** (centipede/mc mechanism). A number with no claim fails the coverage sweep.
- **Encoding traps** — hex radix (`#xx`); the `SCORING TABLE` at `2b17` is little-endian **BCD ×10** (`2b1b 20 00` → 200, `2b21 60 01` → 1600, fruit `2b23 10 00` → 100). Cite the raw byte AND the decoded value; the Dossier decodes.
- **Frightened-mode randomness is deterministic** — draw from `@shared/rng` seeded per game; never ambient randomness.
- **Four files + three registrations** to add the game; regenerate the registry, never hand-edit `src/host/registry.ts`.
- **Logical backbuffer, integer scale** — render into a fixed 224×288 logical canvas, blit integer-scaled to the visible canvas (the centipede AC-2 crisp-pixel rule).

## Self-Review

- **Spec coverage:** every §-section of the design maps to a task — placement/registrations→T1, ground-truth+gate→T2, maze→T3, core modules→T3–T8, testing→gates in T2 + per-task TDD. Deferred items (sound, cutscenes, kill-screen, attract) are explicitly out.
- **Placeholder scan:** numeric oracles are deliberately sourced to `pacman.asm:<addr>` via `glossary.md` (Task 2's deliverable) rather than fabricated — the correct provenance rule for a fidelity repo, not a placeholder.
- **Type consistency:** `Actor`, `Tile`, `TileKind`, `targetTile`, `stepGhost`, `stepMode`, `LEVELS` are named identically across the interface blocks that produce and consume them.
