# Pac-Man (pm2) Implementation Plan — Authentic Namco WSG Sound

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the ninth cabinet its voice — a runtime-synthesised, ROM-faithful **Namco 3-voice WSG** sound layer, driven entirely by the `events.ts` seam pm1 already built and left idle. When this ships, a `just serve` playthrough wakkas as it eats, sirens as the ghosts hunt, and plays the death melody — none of it fetched, all of it synthesised.

**Architecture:** All sound is **shell-side**. pm1's `src/core/` stays pure and untouched: `game.ts` already emits a `GameEvent` for every cue a sound layer needs, and `events.ts` is that union. pm2 adds a shell audio driver that subscribes to those events and a WSG voice built on `@shared/synth`/`@shared/audio`. The waveform data is **baked into JS** from the vendored PROM (the `tools/speech-bake` LPC precedent), so there is **zero runtime asset fetch** — the star-wars silent-music trap (four `.wav` loops 404'd on R2, feature absent from ship; architect gotcha `SWMUS`) is structurally impossible here.

**Tech Stack:** TypeScript, Vite, Vitest (`pac-man` project), WebAudio via `@shared/synth`/`@shared/audio`, Canvas-adjacent shell only. Node ≥ 22.18.

## Global Constraints

- **Core stays pure & untouched** — pm2 adds NO `src/core/` code and changes NO existing core file. `events.ts` and `game.ts`'s emission are already correct; the work is a new `src/shell/` consumer. `purity.test.ts` must stay green with no new exemptions.
- **ROM always wins** — the source of record is the vendored Z80 disassembly `plugins/pac-man/reference/source/pacman.asm` (program ROM) **plus** the Namco WSG waveform PROM vendored in Task 1. The Pac-Man Dossier is the behavioral **decoder**, not byte truth. Do not offer ROM-vs-shipped as a choice.
- **The waveform PROM is NOT in the tree yet** — `pacman.asm` is the 16KB *program* ROM only. The eight 32-sample 4-bit WSG waveforms live in the separate 256-byte `82s126.3m` PROM, which Task 1 must vendor (MAME `pacman` romset; provenance recorded like `reference/PROVENANCE.md`). A synth constant with no vendored-PROM/`pacman.asm` citation fails the coverage sweep.
- **Harness before constants (the rb4 / pm1-2 lesson)** — Task 1 lands the `claims/sound.json` citation gate BEFORE Task 2 writes a single frequency or sample. Numbers are written *under* the gate, never audited in afterward.
- **GPL firewall** — `shaunlebron/pacman` and any GPL sound port are **read-only oracles**. Never copy a line of code or a data table. MAME is the tiebreaker for hardware behavior.
- **No asset fetch** — waveforms and tune data are baked into TS modules at author time. No `fetch`, no `.wav`, no bucket dependency. Acceptance is "the driver fires the right voice on the right event" (unit-testable) plus a served manual listen — never a green vitest standing in for audible output (the silent-feature trap).
- **Autoplay reality** — WebAudio starts suspended until a user gesture; the driver must resume the context on first input (the `@shared/audio` convention the other cabinets already follow) and degrade silently if audio is unavailable — one missing sound never crashes a frame.

### Task 1: Sound ground truth — vendor the WSG PROM + transcribe effect tables, under a citation gate

**Files:**
- Create: `plugins/pac-man/reference/sound/82s126.3m` (the vendored 256-byte WSG waveform PROM) + a provenance note appended to `reference/PROVENANCE.md`
- Create: `plugins/pac-man/docs/rom-study/claims/sound.json`
- Create/extend: `plugins/pac-man/docs/rom-study/glossary.md` → a new `## Sound (Namco WSG)` section
- Modify: `plugins/pac-man/tools/audit/check-citations.mjs` (+ `.d.mts`) to cover `sound.json`; `tests/audit/citations.test.ts` to include it

**Interfaces:**
- Produces: a byte-verified `claims/sound.json` — the eight WSG waveforms (32 nibbles each) and the effect frequency/duration/waveform-select tables — that Task 2/3/4 read as their only source of numbers.

- [x] **Step 1:** Vendor `82s126.1m` (ROM-corrected from the plan's 82s126.3m; MAME says 1m holds the waveforms, 3m is the "Timing - not used" PROM) from the MAME `pacman` romset into `reference/sound/`; record its SHA + provenance in `reference/PROVENANCE.md` in the same shape as the program-ROM entry. This is the byte source for the 8×32 4-bit waveforms; the program ROM alone cannot supply them.
- [x] **Step 2:** In `pacman.asm`, locate and transcribe the sound-effect data: the WSG register writes near `#3305`, the `Choose sound N` dispatch (writes near `4e8c`/`4e9c`/`4ebc`, e.g. `pacman.asm:31a2`+), and the per-effect frequency/duration tables they index. Decode each into `claims/sound.json` entries `{symbol, value, source, addr, meaning}` — raw byte AND decoded value, the pm1 convention. Where the Dossier decodes an effect the program ROM only indexes, cite the Dossier as decoder and mark it honest-uncited (the `ghostSpeedPct` precedent).
- [x] **Step 3:** Write the eight waveform tables into `sound.json` as `{waveform:N, samples:[...32 nibbles]}` cited to the PROM offset. These are the wavetables Task 2 will bake.
- [x] **Step 4:** Extend `check-citations.mjs` to byte-verify every `sound.json` entry against its cited source (program ROM offset via `git show`/file read, PROM offset for waveforms). A number with no verifiable citation fails.
- [x] **Step 5:** Author the `## Sound (Namco WSG)` glossary section: the chip (3 voices, 20-bit phase accumulator per voice, 4-bit volume, waveform-select), how a frequency word maps to pitch, and the effect roster (munch, energizer/frightened siren, ghost-eaten, fruit, death, extra-life, background siren, start theme).

Run: `npx vitest run --project pac-man` (citations + purity green) then `npm run lint`.
Expected: PASS — the sound gate is live and covers every constant Task 2+ will write.
