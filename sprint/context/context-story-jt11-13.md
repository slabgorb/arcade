## Problem
Found by Reviewer during jt11-6. The player types initials and NOTHING appears on screen: layoutHighscoreScreen is called with (colour, table, entryPrompt) and never receives entry.initials; entryPrompt is fixed once when the screen is entered (promptForRank), and the only other use of the buffer is the commit. So the entry screen shows the heading, the persisted rows and a static prompt, and gives zero feedback for a keystroke. Pre-existing since jt10-7, but jt11-6 added an on-screen 'TYPE A-Z   SPACE (FLAP) TO CONFIRM' instruction line, which now actively invites a player to type and see nothing happen. The ROM echoes every character: ENTRET BSR OUTHSC 'WRITE THE CHARACTER' (TB12REV1.SRC:1267) -> OUTHSC writes it at the cursor via OUTCHR (:1271-1276), with WRCUR/ERCUR drawing and erasing a cursor glyph (:1287-1295); the buffer is pre-filled with CSPC spaces (:1901-1905), so unentered slots show as blanks. FONT35 carries a cursor glyph already ('ARRW', the SARRW cell, MESSAGE.SRC:343) plus the space glyph. Fix: thread the in-flight buffer into layoutHighscoreScreen as its own laid-out line (initials padded to MAX_INITIALS so the slots are visible) and paint it in renderHighscoreScreen; cite the ROM echo lines. Verify by looking at /joust/ - this one is only really done when a human sees a letter appear.
