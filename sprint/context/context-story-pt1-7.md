## Problem
Playtest 2026-08-19 (defender's tile surfaced it): the control hint on a lobby tile
just says "keyboard" — it should display the real bindings per game.

## Findings (research complete)

**No contract change needed — this is a manifest DATA fix + regen.** The seam
already exists end-to-end: `GameMeta.controls: readonly string[]`
(`src/host/contract.ts:46`, required/non-empty/non-blank `:143-149`), copied
verbatim by `scripts/gen-registry.mjs:98-106`, rendered one
`<span class="tile-control">` per string by `lobby/src/shell/tiles.ts:80-85`
(textContent only, vertical stack CSS at `lobby/index.html:420-428` — 2-3 lines fit
fine; missile-command already ships a two-liner). The literal "Keyboard" is not in
the lobby at all — it comes from `plugins/defender/plugin.ts:18`.

**Offenders vs. the fleet standard** (most manifests are already good — e.g.
tempest `['ROTATE — Wheel / ←→', 'FIRE — Click / Space']`):
- **defender** `plugins/defender/plugin.ts:18` — `['Keyboard']` ← the bug
- **centipede** `plugins/centipede/plugin.ts:9` — `['Mouse']` ← incomplete
- **millipede** `plugins/millipede/plugin.ts:17` — `['Mouse / Trackball']` ←
  incomplete (its `:10-11` comment self-declares a placeholder; dossier OQ-4)
- **pac-man** `plugins/pac-man/plugin.ts:9` — `['Joystick — ←↑↓→ / WASD']` — fine,
  but omits start keys; judgment call

**Ground-truth bindings (from each shell) for the new strings:**
- defender `src/shell/input.ts:17-28,49`: thrust D/→, reverse A/←, up W/↑,
  down S/↓, fire Space/Enter, smart bomb B/LeftShift, hyperspace H/RightShift,
  start Enter/1. Suggested: `['MOVE — WASD / Arrows', 'FIRE — Space',
  'SMART BOMB — B', 'HYPERSPACE — H']`
- centipede `src/shell/input.ts:96-105`: pointer-lock mouse + left-button fire;
  Arrows/WASD move, Space fire, Enter start. Suggested:
  `['MOVE — Mouse / Arrows / WASD', 'FIRE — Click / Space']`
- millipede `src/main.ts:97,113-118`: pointer-lock mouse, fire
  Space/Enter/Ctrl/Z/X/↑, click fires+starts. Suggested:
  `['MOVE — Mouse / Trackball', 'FIRE — Click / Space']`

**Format trap (load-bearing):** `gen-registry.mjs:76` reads `controls` with a
single-line regex and parses via `JSON.parse(raw.replace(/'/g,'"'))` — the array
must stay ONE line, single-quoted, and contain NO apostrophes in values. Em-dashes
and arrows are preserved byte-for-byte (`src/host/contract.test.ts:244-247`).

**Drift risk to flag:** seven games hand-maintain a second keybind list in the ESC
pause card (`@shared/esc-overlay` `lines`, `src/shared/esc-overlay.ts:17-19`).
Fixing manifest strings makes a third copy (bindings / ESC card / manifest). Keep
the strings consistent with each game's ESC card where one exists; defender has no
ESC card at all (a separate observation, not this story's scope).

## Technical Approach
1. Edit `controls` in the offending `plugins/<id>/plugin.ts` manifests (defender,
   centipede, millipede; optionally pac-man start keys) using the ground-truth
   bindings above, obeying the one-line/no-apostrophe format rule.
2. `npm run gen:registry` — MANDATORY; `tests/registry.test.mjs:41-47` requires the
   committed `src/host/registry.ts` to byte-match a fresh generation, and
   `src/host/registry.test.ts:41-64` compares manifests field-for-field.
3. Verify: `node scripts/gen-registry.mjs --check`, vitest lobby + host projects,
   `npm run test:orchestrator`.
