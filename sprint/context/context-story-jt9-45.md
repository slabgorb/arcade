## Problem
jt9-44 ported only the Y-lane spatial spread of the ptero wave spawn. The ROM implements three entry behaviours; two remain unported:
1. **Random entry SIDE:** Each ptero enters from a randomly-selected screen edge (left/right), not all at posX 8 (PTERST `JSR VRAND / BCC → ELEFT/ERIGHT`, JOUSTRV4.SRC:1421-1489).
2. **TIME-stagger:** Pteros are created incrementally with ≥65-frame intervals, not all on the same frame (PTERWV `PCNAP 65` between creates, JOUSTRV4.SRC:2618).

## Technical Approach
Port the random-side and time-stagger entry mechanics into `spawnWavePteros` (demo.ts). Both are seeded via the deterministic RNG (`@shared/rng` or joust core RNG). Budget for jt2 seeded-replay fingerprint moves per the jt9 standing rule; re-find every moved pin by sweeping for its own precondition.

## Scope
- In scope: random entry side (VRAND-seeded branch per ptero), time-stagger (≥65-frame intervals), deterministic seeded replay, core purity.
- Out of scope: changes unrelated to ptero entry mechanics; remountEnemyProcess sim bug (filed jt9-47).

## Acceptance Criteria
1. **Random entry side is seeded-deterministic:** Each ptero in a multi-ptero wave enters from a randomly-selected screen edge (left or right), NOT all at posX 8. The port uses the deterministic RNG to assign each ptero a distinct entry-side offset matching PTERST's `JSR VRAND / BCC → ELEFT/ERIGHT` (JOUSTRV4.SRC:1421-1489). A seeded replay with the same seed produces the same entry-side sequence.

2. **Time-stagger is seeded-deterministic:** Pteros are created incrementally with ≥65-frame intervals between creations, NOT all on the same frame. The port implements the interval per PTERWV's `PCNAP 65` (JOUSTRV4.SRC:2618). A test fixture seeded with a known seed measures frame deltas between `spawnWavePteros` creations and asserts each interval ≥65 frames (or equivalent: frames N, N+65, N+130 for a 3-ptero wave).

3. **Test non-vacuity control:** A test that compares old (all-same-frame, all-posX-8) to new (staggered, varied-posX) behaviour shows the old produces identical entity digests/coordinates on spawn, while the new produces distinct coordinates and creation frames. The control confirms the test can see the difference.

4. **Determinism is preserved:** The jt2 seeded-replay fingerprints (demo-replay audio, entity state anchors, frame digests) are re-baselined. Every moved pin is re-found by sweeping for its own precondition (never by nudging a number toward the new output). Use the method from sprint/archive/jt5-8-session.md. Any pin that changed seed or anchor is called out and justified.

5. **Core purity is maintained:** The RNG logic lives in `src/core/` (pure). No `window.`/`document.`/`Date.now()`/`Math.random()` calls. The purity/core-boundary guard (`npx vitest run --project joust`) is green.

6. **jt9-44's Y-lane spread is preserved:** The spatial spread porting CLIF5/CLIF3/CLIF1 remains intact; this story adds side + time on top. Mutation: revert the stagger or side-randomization → test RED. Control: both stagger and side must co-exist to green.
