Missile Command — authentic play & feel, round 3 (owner playtest 2026-08-16): the MIRV swarm, the incoming lollipop, the placeholder bomber/satellite, and trackball aim

## Overview
Twelfth Missile Command epic, born from the owner's own playthrough of the current
build (2026-08-16, four findings + a screenshot of a MIRV fan) — the mc10 pattern:
mc9/mc10 shipped the DATA (stamps, palette, HUD, blast curve) and mc11 wired the
unwired seams, but playing it surfaces four things that still read wrong versus the
real cabinet. Architect (Vito Cornelius) diagnosis, each verified against the vendored
REV-01 source (plugins/missile-command/reference/source) and pinned to file:line.

(1) MIRV OVER-PRODUCTION — the difficulty driver. The owner cannot progress or break
the top-10 ("do we create multiple warheads too quickly"), and the screenshot shows a
single MIRV fanning into ~6 warheads from one point. Cause, read in code: mirvSplit
(core/mirv.ts:50) launches its 3 children AT parent.pos, whose height is inside the
MIRV band [MIRVLO=128, MIRVHI=160] (W3COMN.MAC:159/161), and game.ts:597-600 appends
the children while LEAVING the split parent in the list with no "spent" marker — so
every frame the in-band cluster re-qualifies (mirvEligible, mirv.ts:38) and re-splits,
bounded only by the NICBMS=8 slot ceiling. The ROM splits each ICBM ONCE: MIRVIX is a
single "ICBM TO MIRV (INDEX)" slot (W3MAIN.MAC:227), the split consumes it
(W3MAIN.MAC:2011-2017), and POTENT caps "NO MORE THAN 3 SHOTS FROM A MIRV"
(W3MAIN.MAC:2717). DECISION (ROM-always-wins): bound a MIRVed ICBM and its children so
they never re-split — no invented difficulty knob. (mc12-1)

(2) THE INCOMING "LOLLIPOP" — render.ts:175 fills a headR≈width/200 disc (ctx.arc) at
each ICBM head, reading as a ball on a stick. The cabinet draws incoming missiles as a
trail with a flashing 1px tip, exactly like the ABM ("TIP OF MISSILE TRAIL IS FLASH",
W3DSUP.MAC:931; DRAW MISSILE, W3DSUP.MAC:1221) — no disc. (mc12-2a)

(3) BOMBER/SATELLITE ARE A PLACEHOLDER RECTANGLE — render.ts:186-189 draws every
sputnik/plane as a fillRect wing/box whose own comment defers the real sprite to mc9;
mc9-1 only ever did city/base stamps, so planes still read as "a tiny rectangle" (owner
report). Port the plane (bomber) and satellite (sputnik) stamp geometry from the W3DSUP
stamp layer, as mc9-1 did for cities (WRITE A STAMP, W3DSUP.MAC:587; claim sputnik.json
already exists). (mc12-2b)

(4) AIM SHOULD BE POINTER-LOCKED (trackball), like centipede/millipede. Missile Command
is a TRACKBALL cabinet; mc10-1 made aim ABSOLUTE to kill the twitch of relative-WITHOUT-
lock (1px=1unit over a ~2000px canvas) and explicitly deferred "trackball (relative +
pointer-lock, scaled) as an optional later mode". This epic BUILDS that mode and makes
it the default, reusing centipede/millipede's createPointerLock + movementX/Y adapter
and the existing pure core moveCursor — completing mc10-1, not overturning its fix
(logged as an ADR-delta, never a silent reversal). (mc12-3)

A final VISUAL playtest verifies all four IN THE BUILD, not just green vitest — the
mc9->mc10 lesson was green-tests/wrong-pixels, and this whole epic is a playtest's
output. (mc12-4)
