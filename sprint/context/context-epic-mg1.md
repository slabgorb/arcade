### The through-line: every story here demands a test that CAN fail

This is not a coincidence across the ACs, it is the epic's charter. Read them together:

- **mg1-2** — "an all-200 sweep of known paths is explicitly insufficient"; requires a nonsense
  control path and a DIFFERS assertion.
- **mg1-3** — "the guarding assertion is the NEGATIVE — that no `<game>/` key appears in the lobby
  leg's upload set. A test that merely confirms the lobby's own files are present passes both
  before and after the regression."
- **mg1-5** — "a test proves the ordering holds for a fixture whose HTML filename sorts BEFORE its
  assets, since the current behaviour passes trivially"; and asserting a non-zero exit "is not
  enough — it already does that."
- **mg1-4** — the guard "must read the registry rather than hardcoding the valid set, or it becomes
  the next stale list."

Several of these stories exist *because* a vacuous check was caught. The migration's recurring
failure shape is an assertion that is green against both the bug and the fix. Before handing any
mg1 test to review, delete the fix and require red — a guard that was never mutation-tested is
scenery.

### Route to the ORCHESTRATOR suite, not vitest

Almost every mg1 story touches cabinet wiring rather than game code: `vite.config.ts` (mg1-2),
`.github/workflows/deploy.yml` + `tests/monorepo-topology.test.mjs` (mg1-3), sprint YAML (mg1-4),
`scripts/deploy-r2.mjs` (mg1-5). Those are guarded by `npm run test:orchestrator`
(`tests/**/*.test.mjs`, `node:test`) — **vitest never sees them**. A TEA who reaches for
`npx vitest run` by reflex will write the test in the wrong runner and it will not run in the
release path. The two suites do not overlap.

### Preserve the accounting, don't erase it

Several targets in this epic are deliberate historical records, and the ACs say so in different
words each time: mg1-2 requires the Task 19 tripwire be *updated* so "the invariant moves instead
of evaporating"; mg1-1 forbids silently rewriting a frozen audit doc out of existence; mg1-4
requires historical stories be handled "deliberately … with the choice stated so the next reader
does not treat it as an oversight". The header comment in `tests/canonical-serve.test.mjs` is the
house style: retired assertions are quoted by their exact old title with the reason. Follow it.

tell an agent to work in a directory that moved to `plugins/<id>/`. Until mg1-4 lands, trust the
paths in this file over any `repos` value you read elsewhere in the sprint.
