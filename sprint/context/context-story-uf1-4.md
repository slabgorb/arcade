## Problem
Of the 19 exports in star-wars/src/core/trench-wedges.ts, only 6 reach production code — buildTrench, wedgeLength, trenchPortDistance, TRENCH_PORT_OFFSET, PANEL_FORCEFIELD and the Wedge type. The other 13 are referenced by tests and by nothing else: the panel-column vocabulary (PANEL_BLANK, PANEL_PANEL, PANEL_GUN, PanelColumn, decodePanelColumn), the five wedge-type opcodes (WEDGE_SHORT, WEDGE_LONG, WEDGE_END, WEDGE_PORT, WEDGE_NEXT), and the pie and group layer (PIES, WEDGE_GROUP_IDS, wedgeGroup). This is the sw7-6 gap, now half closed: sw7-22 landed streamForceFields (trench-obstacles.ts:207, called from sim.ts:1763), so PANEL_FORCEFIELD alone graduated from the grid into the running trench. Wall guns did not — trench gun behaviour still lands on legacy TrenchObstacle entities via TRENCH_GUN_FIRE_MASK (sim.ts:1306), not on the grid's PANEL_GUN columns. Two honest outcomes and the story should pick one per symbol rather than assuming: WIRE the remaining grid layer so guns, panels and pies are streamed from the decoded wedge data the way force fields now are, or RETIRE what the port genuinely does not consume and say so in the module header. Do not leave a third state where the data sits tested and unread — that is what this story exists to end. streamForceFields is the reference implementation for the wiring direction.

## Acceptance Criteria
- Every one of the 13 currently test-only exports has an explicit disposition — wired to a production consumer, or removed, or documented in the module header as ROM data deliberately carried without a consumer and why.
- If PANEL_GUN is wired, trench wall guns are streamed from the decoded grid columns rather than placed as legacy TrenchObstacle entities, and the change is proven by a test that moves a gun by changing grid data alone.
- streamForceFields keeps working unchanged, or its change is a deliberate logged deviation — sw7-22's shipped behaviour is not collateral.
- The run-duration and object-count ceilings that blocked sw7-19's dense grid are respected: any newly streamed layer is measured empirically, not assumed cheap.
- No symbol in trench-wedges.ts is left referenced only by tests when the story closes; a repeat of the sweep's export scan over this module returns clean.
- The module header states which layers of the wedge grid production consumes, so the next reader does not have to re-derive it.
