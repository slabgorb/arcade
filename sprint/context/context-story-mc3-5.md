## Problem
Plan tasks 8-10 (docs/superpowers/plans/2026-08-07-missile-command-mc3-core-loop.md). The shell + integration that makes mc3 visibly playable. (a) shell/render.ts — draw incoming ICBM trails+heads, dead cities/bases as rubble (only live structures draw intact), and a HUD showing state.score and each base's ammo; functional colours only (per-wave palette + authentic stamps are mc9); the HUD score is the core's state.score, never a re-derived copy. (b) shell/input.ts — a destroyed or empty (ammo=0) base cannot fire (no-op); a successful shot appends the ABM and decrements that base's ammo by 1; keep the existing per-key->base mapping. (c) tests/mc3-playthrough.test.ts — one seeded end-to-end run asserting the loop is coherent (enemies appear, budget draws down, MXICON respected, structures monotonic, phase in {play,over}) and fully deterministic. Read the existing render-field.test.ts / fire.test.ts harness first and match it. Depends on mc3-4.
