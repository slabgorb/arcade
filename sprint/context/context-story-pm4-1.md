# Story pm4-1 Context

## Title
[SAFETY] Remove the full-screen white level-clear strobe (shell overlays.ts): delete the fillRect(0,0,LOGICAL_W,LOGICAL_H) white fill; hold a brief static frame instead. Zero full-screen luminance flashing (boss has photosensitive epilepsy). Shell-only, independent of the state machine, shippable immediately. pm4-4 later builds the proper freeze on top and MUST NOT reintroduce the strobe.

## Problem
`plugins/pac-man/src/shell/overlays.ts` reacts to the `level-cleared` event by
filling the **entire 224×288 logical buffer** with solid white and strobing it:

- Constants (top of `createOverlays` region): `FLASH_COLOR = '#ffffff'`,
  `FLASH_HALF_PERIOD = 8`, `FLASH_CYCLES = 6`, `FLASH_FRAMES = 96`.
- In `draw(...)`: when `flashFramesLeft > 0`, on the "on" half-cycle it runs
  `ctx.fillStyle = FLASH_COLOR; ctx.fillRect(0, 0, LOGICAL_W, LOGICAL_H)` then
  decrements. That is a full-screen white flash at ~60/16 ≈ **3.75 Hz for 96
  frames**.
- `onEvents(...)` latches it: `case 'level-cleared': flashFramesLeft = FLASH_FRAMES`.

Worse, the sim never freezes during this: `core/game.ts`'s `advanceLevel` runs on
the same frame the `level-cleared` event fires, so the strobe plays **over live
play**.

**This is a photosensitive-epilepsy seizure hazard** (the boss has photosensitive
epilepsy) and is also non-authentic — the arcade recolors maze *walls*, never the
whole screen. Removing it is a p0 safety fix.

## Technical Approach
Shell-only. Replace the full-screen flashing fill in `overlays.ts` with behavior
that produces **no full-screen, high-luminance, rapidly-changing** output on
level clear — a brief STATIC hold (or simply no overlay at all) is acceptable for
this story. **Keep** the `level-cleared` latch/plumbing (the `flashFramesLeft`
counter or an equivalent hold timer) so the successor story **pm4-7** (freeze
pauses) can layer the proper sim-freeze on top; pm4-7 MUST NOT reintroduce any
strobe. Core (`src/core`) is out of scope. No ROM citations apply — this is an
accessibility change, not a fidelity constant (N/A for `citations.test.ts`).

Design reference: `docs/superpowers/specs/2026-08-09-pac-man-cabinet-lifecycle-design.md`
(Track A / pm4-1). Note: the design's proposed successor number "pm4-4" was
renumbered on materialization — the freeze-pauses successor is **pm4-7**.

## Scope
- **In scope:** `plugins/pac-man/src/shell/overlays.ts` (and its test under
  `plugins/pac-man/tests/shell/` if one exists) — remove the full-screen
  level-clear strobe.
- **Out of scope:** any `src/core` change; the sim-freeze/pause behavior (that is
  pm4-7); the state machine (pm4-5+).

## Acceptance Criteria
1. On the `level-cleared` event, `overlays.ts` no longer fills the full logical
   buffer (`fillRect(0,0,LOGICAL_W,LOGICAL_H)`) with a flashing or high-luminance
   color — assert the full-screen white fill path is gone.
2. No rapid (>3 Hz) or large-area high-luminance transition remains in the
   level-clear render path.
3. The pac-man vitest project stays green: `npx vitest run --project pac-man`.
4. Purity/orchestrator suites are unaffected (shell-only change; core untouched).
