The windshield crack is a HIT reaction, not a permanent decal — gate it on player-hit state

## Problem
The lead bug. drawCrackedGlass(ctx, w, h) is called UNCONDITIONALLY every frame (plugins/battlezone/src/main.ts:276), so the viewport "starts cracked" the instant a run begins. On the real cabinet the shattered-glass graphic is the tank's hit/ destruction reaction — the periscope shatters when you are killed, then clears on respawn. The ROM already models the trigger: bz4-1 shipped BOUNCE=0xFF on the player-death / windshield-crack path (BZONE.MAC:2337-2338), and the render comment (render.ts:329-333, "dis65 @ $6140") already documents the crack as the death-path graphic. What is missing is the WIRING: the shell must draw the crack only while the player is in the hit/dying state and clear it on respawn, instead of always. Thread a pure, observable "windshield cracked" flag off the existing death/hit event in core (events.ts / state.ts / sim.ts) — do NOT compute it in the shell — and gate drawCrackedGlass on it. Keep the crack geometry (CRACK_PATHS) as-is; only its VISIBILITY changes. Cross-check the trigger against MAME's death handling so the appear/clear timing matches the executed ROM, not just the disassembly line.
