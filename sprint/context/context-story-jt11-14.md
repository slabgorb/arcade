## Problem
Found by Reviewer during jt11-6. jt11-6 gave the entry screen a 7680-tick budget (ROM: AMODE's 256 x PCNAP 30, TB12REV1.SRC:77-78) that auto-commits the current initials when it runs out, so a walked-away qualifying score persists. But the budget is spent inside pumpFrames, driven by requestAnimationFrame, and MAX_CATCHUP_SECONDS = 0.25 discards elapsed wall time - so the countdown FREEZES while the tab is hidden and never advances if the tab is closed. The most literal reading of 'walked away' (hide or close the tab) is therefore the one case the fix does not serve; it works for the visible-cabinet case, which is the arcade case and was the point. Fix: commit the in-flight entry on pagehide (and/or visibilitychange to hidden) while cabinet.mode === 'highscore', through the SAME commitHighScore helper - main.ts asserts exactly one highScores.save( and one commitEntry( call site, and that invariant must survive. Note the listener is shell-only; core still counts ticks and must not learn about the document. Test the seam the way jt11-6 did: a source-scan on the pump/handler wiring plus a mutation to prove the guard bites.
