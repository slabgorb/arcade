## Critical Correction — Title Premise Refuted

> ⚠ **The title's "identical narrowing type" premise is FALSE** (measured 2026-08-11). Only 3 of the 7 games share the exact member set `{play, startLoop, stopLoop}`, and only 2 name it `SoundPlayer`. The real shared surface is a PATTERN (a `for/switch/exhaustive-never` skeleton plus game-specific ROM cue maps), not a constant type. The **Architect will decide the extractable surface before RED** — the honest answer may be "lift a thin shared convention / a generic Pick helper, and leave game-specific slices and switch bodies alone."

### Measured Type Narrowing across the 7 Games (verified 2026-08-11)

| Game | Type Name | Narrowing Members |
|------|-----------|-------------------|
| asteroids | `SoundPlayer` | `play`, `startLoop`, `stopLoop` |
| tempest | `SoundPlayer` | `play`, `startLoop`, `stopLoop` |
| missile-command | `SoundSurface` | `play`, `startLoop`, `stopLoop` (+ `DroneSurface` = `startLoop`, `stopLoop`, `feedDrone`) |
| battlezone | `SoundSurface` | `play`, `startLoop`, `stopLoop`, `setEngine`, `stopEngine` |
| centipede | `SoundSurface` | `play`, `startLoop`, `stopLoop`, `tick` |
| joust | `SoundPlayer` | `play`, `tick` (joust NEVER loops) |
| red-baron | `SoundSurface` | `play`, `playTone`, `setEngine`, `setGun`, `setApproach` |

**Pattern:** Each game defines a game-specific narrowing of `AudioEngine` methods. The shared PATTERN is the `type X = Pick<AudioEngine, ...>` declaration plus the `for (const event of events) switch(event.kind){...} default: const _exhaustive: never = event` skeleton. Each switch body is that game's own ROM cue map and cannot be unified.
