## Critical Correction — Title Premise Refuted

> ⚠ **The title's "identical narrowing type" premise is FALSE** (measured 2026-08-11). Only 3 of the 7 games share the exact member set `{play, startLoop, stopLoop}`, and only 2 name it `SoundPlayer`. The real shared surface is a PATTERN (a `for/switch/exhaustive-never` skeleton plus game-specific ROM cue maps), not a constant type. The **Architect will decide the extractable surface before RED** — the honest answer may be "lift a thin shared convention / a generic Pick helper, and leave game-specific slices and switch bodies alone."

## Design Gate Decision (Architect — SH4-5)

**Verdict: EXTRACT NOTHING into `src/shared`. Pin the convention instead.**
The mechanism the pattern rests on is *already* extracted; what remains duplicated
is a ~6-line idiom plus seven game-specific ROM cue maps that the epic's own
guiding rule ("share the VERB, not the NUMBERS") says must stay in the games.
SH4-5 ships a convention document plus an AST-based orchestrator guard test, and
**zero changes under `plugins/` and zero new runtime exports from `src/shared`**.

### Evidence (measured 2026-08-11, this tree — extends the table above)

1. **The shared surface already exists.** `src/shared/audio.ts` exports the generic
   `AudioEngine<N extends string>` — `{resume, play, startLoop, stopLoop, ready, tick}` —
   plus `createAudioEngine`. Three games alias it outright
   (`export type AudioEngine = SharedAudioEngine<SoundName>`: tempest `audio.ts:94`,
   joust `:144`, centipede `:252`); asteroids and star-wars build ON the shared engine
   but export their own interface; battlezone and red-baron (runtime synthesis) and
   missile-command (POKEY worklet) hand-roll engines with game-specific verbs
   (`setEngine/stopEngine`, `playTone/setGun/setApproach`, `feedDrone`). So the type the
   title wants lifted is a `Pick` over SEVEN DIFFERENT engine types, of which only three
   are the shared generic. The extractable engine contract was lifted in prior epics;
   this story found the residue, not a missed lift.
2. **All 7 dispatchers already use the same mechanism: `Pick<AudioEngine, …>` from their
   own `./audio`.** `Pick` is the TypeScript builtin — there is no algorithm here to
   extract, only a name.
3. **The "skeleton" diverges far more than the title assumes:**
   - **joust** — `cueFor(event): SoundName | null` helper; unconditional `audio.tick()`
     FIRST (the machine's frame clock, SYSTEM.SRC:173-187); no loops at all (a ROM fact:
     every sound table self-terminates, JOUSTRV4.SRC:8045-8049).
   - **centipede** — not a kind-switch at all: a typed `Record<GameEventKind, SoundName>`
     table (`EVENT_SOUND`, exhaustive at its *declaration* in `audio.ts`) + an
     `effectFor` name-convention switch + tick-first. It already IS the table-driven
     form, locally, in the one game uniform enough to permit it.
   - **battlezone / red-baron** — a second export `updateContinuousSounds(audio, …)`
     driving voices that have no trigger event to ride.
   - **missile-command** — THREE exports: `playEventSounds`, `updateSustainedSounds` on a
     second narrowed slice (`DroneSurface`), `playEdgeCues(audio, prev, curr)` over state
     pairs.
   - **asteroids** — nested switch on `event.source` with its own inner never-guard.
   - **tempest** — multi-call bodies (`warp-space` = `stopLoop`+`startLoop` hand-off) and
     deliberately-silent cases carrying fidelity rulings in comments.
   - **Invariant across all 7:** an explicit `const _x: never = …` exhaustiveness anchor,
     and degrade-don't-throw at runtime (frame-path rule — cp5-2 user ruling 2026-08-01;
     joust and centipede document it identically).
4. **Counter-models prove the pattern is a convention, not a universal.**
   pac-man folds the same event→voice dispatch inline into `createAudioDriver` — a
   STATEFUL closure (munch alternation, `deathHold` counter, ambient warble phase) that a
   stateless shared skeleton cannot host. star-wars has no standalone dispatch file — its
   event→cue SELECTION is the same `switch (event.type)` + `const _exhaustive: never`
   guard as the seven, inlined in `main.ts:148-259`; its lookup tables (`SOUNDS`/`CHANNELS`)
   resolve a sound NAME to a file/channel inside the engine (SH2-16), a separate step from
   selection, alongside speech/tune channels on separate engine instances.

### Rejected alternatives

- **R1 — table-driven / higher-order `makeEventDispatcher`.** The generic saves the
  3-line `for` loop per game and must grow hooks for: tick-first ordering (joust,
  centipede), continuous/edge companions (battlezone, red-baron, missile-command),
  per-event payload narrowing (mapped handler types keyed on the discriminant), nested
  discriminants (asteroids `event.source`), multi-call and deliberately-silent bodies
  (tempest). The config surface exceeds the code replaced, and it forces seven
  behavior-neutral rewrites of audited, cited cue maps — pure regression risk for zero
  user-visible gain. The epic's own bar: an extraction that changes output is a
  regression, not a refactor.
- **R2 — a shared `SoundPlayer<N>` alias (`Pick<AudioEngine<N>, 'play'|'startLoop'|'stopLoop'>`).**
  Matches the member set of only 3 of 7 (asteroids, tempest, missile-command), and of
  those only tempest's engine IS the shared generic — for the other two it would have to
  be a structural type, *decoupling* the dispatch param from the game's actual engine
  (today the local `Pick` tracks the local engine's signatures automatically; that
  coupling is a feature). An alias of a builtin is a name, not a mechanism — below
  ADR-0001's bar ("a shared name or shape is NOT enough", this epic's own words).
- **R3 — force all 7 onto one type name/member set.** Refuted by the measured table
  above: it would invent loops for joust (the ROM has no sustained voice) or amputate
  battlezone/red-baron/missile-command's game-specific verbs. Lossy by construction.
- **R4 — a shared `unreachable(x: never)` helper.** A 2-line idiom; the epic already
  deferred one-expression primitives (`mod(v,size)`) as below the bar. Same ruling.

**The convention (5 clauses), to be recorded in `src/shared/audio.ts`'s header:**
1. A game's event→cue wiring lives in `src/shell/audio-dispatch.ts` as PURE importable
   functions (no module state, no DOM) — unit-testable against a recording fake,
   node-importable.
2. Every dispatch function takes a NARROWED same-file `Pick<AudioEngine, …>` slice —
   never the full engine.
3. Exhaustiveness is compile-time, anchored by an explicit `never`-typed binding
   (in the kind-switch, or at a typed `Record` declaration + closed-union switch —
   the centipede form).
4. Runtime DEGRADES, never throws: this runs on the frame path, where a throw freezes
   the game and a wrong sound is worse than a missing one.
5. Switch/table BODIES are that game's own ROM cue map, cited to its assembler — they
   are never unified, tabled, or shared across games.

Purity note: nothing here touches any `src/core`; the guard reads source via the TS AST
from `tests/` (outside every game's purity-scanner scope); audio-dispatch remains shell.

### Derived Acceptance Criteria (for TEA — RED targets)

The guard is `tests/audio-dispatch-convention.test.mjs`, node:test, using the
**`typescript` compiler API** (devDep `^5.4.0`) — AST, not regex/line-grep (the mc10-6
ruling: text scans leak through comments and enclosing declarations; the AST is
trivia-blind, so comment prose can never satisfy a check).

- **AC-1 (identity, not count):** the guard enumerates plugins owning
  `src/shell/audio-dispatch.ts` and asserts the SET is exactly
  `{asteroids, battlezone, centipede, joust, missile-command, red-baron, tempest}` —
  set equality, not `length === 7`. Adding or removing a dispatch file is a deliberate
  one-line baseline update, and a new file automatically enters AC-2/AC-3's sweep.
  (pac-man and star-wars are thereby pinned as deliberate exemptions.)
- **AC-2 (narrowed param, AST):** in each of the 7 files, every exported function whose
  first parameter is the audio surface types it via a TypeReference to a SAME-FILE
  `type X = Pick<AudioEngine, …>` alias; equivalently and more simply: **no parameter
  anywhere in the file is typed bare `AudioEngine`**. Covers the secondary exports
  (`updateContinuousSounds`, `updateSustainedSounds`, `playEdgeCues`) for free.
- **AC-3 (exhaustiveness anchor, AST):** each of the 7 files contains at least one
  VariableDeclaration with an explicit `never` type annotation inside a function body.
- **AC-4 (controls / mutation resistance, restrictive direction):** the test ships
  inline negative fixtures run through the SAME predicates: (a) a source string whose
  dispatch param is bare `AudioEngine` must FAIL AC-2's predicate; (b) a source string
  whose only `never` anchor lives in a comment must FAIL AC-3's predicate; (c) a minimal
  compliant fixture must PASS both. No working-tree mutation needed, and the guard can
  never be satisfied by prose.
- **AC-5 (no-regression / no-lift):** `npm run test:orchestrator` green including the
  new guard; `npx vitest run` green and untouched; `git diff` shows no changes under
  `plugins/`; `src/shared/audio.ts` diff is comment-only (no runtime export added or
  changed). The convention paragraph's presence is a Reviewer checklist item, not a
  prose-grepping test.

**Explicitly NOT asserted:** any single shared type name, any shared member set, any
shared dispatcher function — the measured table refutes all three.
