## Problem
Playtest 2026-08-19: the spawning (materialize/warp-in) animation renders as an
opaque overlay; it should be transparent per the arcade's shimmer.

## Findings (research complete — shell-only, no sim cascade)

**Terminology:** the effect is WARP-IN / TREFF (`src/core/warpin.ts` — which
names `dissolve.ts` as "the false friend": that's the ptero death ash, not this).

**The draw:** `src/shell/render.ts:279-305` `paintWarpIn` paints two OPAQUE
owner-coloured boxes — the pad bar (`:296`) and a growing 16-wide "bird" bar
(`:303`); defaults `:257-260`. It never reads `op.name`'s pixels, though the op
already carries the STAND sprite name (`sim.ts:3220-3238` `warpInOp`). Dispatch
at `main.ts:348` REPLACES the sprite (before `blitOp`), so the box is all you
see. `tests/render-warpin-jt13-2.test.ts:10-15` records this as a deliberate
deferral ("pixel-accurate WCLENY silhouette clipping is deferred") — this story
is that deferral coming due.

**The authentic effect — a TRANSPARENT solid-colour silhouette of the bird's own
sprite:** the ROM blits the sprite with the blitter's SOLID bit ADDED to the
normal zero-suppress (transparent) flavour:
- `SYSTEM.SRC:504/568` `WR1CLS/WR2CLS LDA #$0A` — "ZERO SURPRESS TRANSFER"
- `JOUSTRV4.SRC:5736-5739` — `LDA ,X / ORA #$10` "CONSTANT FILL OF TRANSPORTER",
  `LDB DCONST,Y` colour; same on the bird's DMA block `:5787-5790`
- $0A|$10 = $1A: zero-suppress KEPT, constant-colour added. MAME (prose, pinned
  SHA) confirms bit meanings: `williamsblitter.h:41-42` (SOLID=$10 bit,
  FOREGROUND_ONLY=$08 bit), `williamsblitter.cpp:160-187` (fg-only skips zero
  nibbles; solid substitutes the constant colour). Compare the ERASE flavour
  `CL2CLS #$1A` with constant 0 (`SYSTEM.SRC:535-538`) — TREFF is the same blit
  with DCONST instead of 0.
- The vertical "growth" is WCLENY DMA height on the real sprite
  (`JOUSTRV4.SRC:5750-5757`), feet pinned (`:5763-5772`), clamped to the
  transporter (`:5774-5783`).

**The idiom already in the file:** `paintDissolve` (`render.ts:185-210`) skips
nibble 0 (`:204`), as does the atlas bake (`:144`).

## Technical Approach
Rewrite `paintWarpIn` on the `paintDissolve` idiom: look `op.name` up in the
atlas/PIXEL_BLOCKS, fillRect each NON-ZERO nibble in the single constant colour
(`colours[nibble]` per the owner/idle rules), vertically clipped to the
PFRAME-derived WCLENY height, bottom-anchored at `op.y`. Satisfies both halves:
transparent AND bird-shaped. Shell-only — `warpin.ts` core state, op emission,
and all timing stay untouched.
New claims (none exist — `claims/warpin.json` JT132/JT139 don't cover these):
the two `ORA #$10` ORs (`JOUSTRV4.SRC:5736-5737`, `:5787-5790`) and the
`WR1CLS #$0A` zero-suppress default (`SYSTEM.SRC:504`). MAME facts prose-only.
No strobe concern: the silhouette is a steady constant fill (Decision B safe).
