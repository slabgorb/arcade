## Problem
Playtest 2026-08-19: every enemy in the world is always on screen; the world never scrolls off-camera and the scanner shows the same thing as the main view. ROOT CAUSE (confirmed in code + ROM): the object/terrain/star/collision projection uses `(worldX - camera) >> 8` (scene.ts:398 screenCol, sim.ts:624 toScreenCol, stars.ts 1-unit=1px) with NO visible-window cull, so the full 256-column world (0x10000>>8) is blitted into the 292px raster. The ROM's real object-visibility test (DEFA7.SRC:2527-2530) is `LDD OX16 / SUBD BGL / CMPD #150*64 / BHS OPLP OFF SCREEN` — i.e. objects project at `(OX16-BGL) >> 6` into a 150px window onto a 0x10000/(150*64) ≈ 6.8-SCREEN world; terrain/explosion culls confirm the right edge at $98 (BLK71.SRC:638-645, SAMEXAP7.SRC:74). The port conflated two fixed-point formats: the ship's PLAX16 is pixel.8 (ship at plax16>>8 ∈ [$20,$70]=[32,112]) but OX16 must be pixel.6; sim.ts:535 even mixes them (`camera.bgl + plax16`). FIX (sibling to pt1-3/pt1-4 star-wars projection): reconcile the object/camera coordinate format to the ROM (read the ship-draw AND object-draw pixel computation to lock PLAX16-vs-OX16 scale), project at the ROM scale with a 150px visible window, cull off-window objects (they belong to the scanner only), and move render + collision + laser hit-testing together. Pin the visible-window width and the cull with cited tests (rom-fidelity-audit). HIGH regression risk — collision/scanner/hit-testing/spawn all read the projection; do it TDD with a live playtest verify.
