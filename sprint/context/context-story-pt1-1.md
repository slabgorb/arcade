## Problem
Playtest 2026-08-19: as the playfield shifts down, each unexploded DDT pill leaves
a trail of phantom copies; only one is interactable.

## Findings (research complete — root cause identified, high confidence)

**NOT the scroll remap and NOT the renderer.** The shift remap is present and
correct: `scrollDown` (`src/core/scroll.ts:115-147`) moves field bytes,
`ddtScrollDown` (`src/core/ddt.ts:375-408`) steps the bank (`e.lo -= 1`, DD-53),
both wired in `stepGame` (`src/core/sim.ts:404-418`). The renderer reads only the
field (`src/main.ts:253-257` via `fieldPlacements`) — no stale grid.

**Root cause: `sim.ts:361-370` re-runs DDTS at EVERY wave start, which the ROM
never does.** The wave-ready branch calls `ddtPlace(state.ddt, false)` +
`ddtRestore(state.ddt, state.field)` — resetting all four bank entries to the
fixed `DDTST` rows (`ddt.ts:72`) and stamping fresh `$6E/$6F` there. In the ROM,
`DDTS` has exactly two callers: `MILLI.MAC:1227` inside INITSC (new game/screen,
right after the playfield CLEAR at `:1215`) and attract init (`MLATR.MAC:59`).
`CENTPC` — the ROM's wave restart (`MILLI.MAC:497-519`) — touches no DDT state.
`DDTS2` (restore-only) is called only at `MLSUB.MAC:68, 673, 1038, 1792`.

The cascade that produces the trail:
1. Each wave, fresh stamps land at the DDTST rows; the previous wave's stamps
   were only ever MOVED by scrolls, never erased (`ddt.ts:389`).
2. `scrollQueued -= 1` per wave (`sim.ts:365`) shifts the field one row — each
   wave's orphan sits one row below the last → a vertical trail.
3. Only the bank copy is real: `ddtShoot` matches shot address against the bank
   (`ddt.ts:221-235`); an unmatched `$6E` → `{kind:'none'}` → `resolveShot`
   `'pass'` (`src/core/shot.ts:54-61`) — shots fly THROUGH phantoms, and
   explosions preserve other bombs (`ddt.ts:276-277`) so they're never cleaned.
4. Aggravation: `restoreCell` (`ddt.ts:188-192`) refuses to overwrite stamps in
   `$01..$6F` — a phantom squatting on a DDTST cell blocks the REAL bomb's stamp.

## Technical Approach
Remove `ddtPlace` + `ddtRestore` from the wave-ready branch in `sim.ts:361-370`;
initial placement stays in `createGame` (`game-state.ts:142-144`, correctly
mirrors INITSC). Optionally add DDTS2-style restores only at the ROM's four
`DDTS2` sites if/when those flows exist. Pure-core change; no new constants —
every DDTS/CENTPC anchor already has a claim in
`docs/rom-study/claims/13-ddt.json` (the citations gate needs nothing new).

## Scope

  stamps 1:1 across a wave boundary + scroll).
- Out of scope: DDT scroll mechanics (`ddtScrollDown` is correct), glyph render,
  explosion logic.
