# Epic mc9 Context

## Title
Missile Command — render fidelity (real graphics)

## Overview
Ninth Missile Command epic — retires the placeholder graphics. Today src/shell/render.ts draws functional stand-ins only: cities are fillRect blocks, bases are triangles, ICBMs are lines+dots, blasts are symmetric-triangle circles, the HUD is monospace, and there is a single hard-coded colour per object with no per-wave palette. mc3-5 shipped that deliberately ('functional colours only, per-wave palette + authentic stamps are mc9') and mc1's blast is 'a symmetric-triangle placeholder ... the exact per-tick OLDRAD curve and EXPFRA cadence are explicitly deferred to mc9'. This epic makes it LOOK like Missile Command: authentic city/base stamps, the per-wave 8-colour palette + colour cycling, authentic missile trails, the exact OLDRAD blast curve, and the cabinet's stroke-font HUD. Missile Command is a RASTER machine drawn by a framebuffer stamp layer (W3DSUP), so 'real graphics' means porting the W3DSUP draw routines/shapes, not vendoring a sprite ROM. Executes the Architect roadmap slice for mc9 in docs/superpowers/specs/2026-08-07-missile-command-full-cabinet-roadmap.md; mc9 may begin any time after mc3 and in parallel with mc4/mc8 since it layers on state the core already emits. The core/shell boundary holds (contract 2): all pixels stay in src/shell; the ONE core touch is the OLDRAD blast-radius curve, which is a cited numeric constant and moves through a claim in explosion.ts. Resolves open question O-5 (per-wave palette / 3rd colour bit / hardware address scramble). Primary anchors (subsystems.md): W3DSUP.MAC:587 WRITE A STAMP; W3DSUP.MAC:1067 DRAW ALL LIVING CITIES; W3DSUP.MAC:1221 DRAW MISSILE; W3DSUP.MAC:1583 SET UP COLORS FOR NEXT WAVE; W3DSUP.MAC:1712 CLEAR SCREEN; W3MAIN.MAC:1811 PROCESS EXPLOSIONS. OUT OF SCOPE: waves/scoring (mc4), audio (mc8), enemy roster (mc5).
