## Technical Approach (as delivered in 758498e5)

The live terrain (`composeFrame`) and the title still (`composeStaticFrame`) both decoded
TDATA via `decodeAltitudes`, which reproduces BGALT/ALTTBL — a table that is filled but
NEVER read anywhere in the vendored ROM source (referenced only at BLK71.SRC:70/:382/:397).
The cabinet's scrolling terrain is instead generated by ADDR01/ADDL01 via RFONR1/LFONR1
(:307,:236,:435,:487): a +/-1 walk consuming ONE bit per world column over all 2048 bits of
TDATA (the whole $10000 world at $20/column). Tiling the 1024-entry BGALT table mod 256 drew
only the first quarter of the planet, at half resolution, stretched across the lap.

The fix adds a pure `decodeScrollSurface(block, worldCols = WORLD_COLS)` (terrain.ts:57) that
walks all 2048 TDATA bits +/-1 per bit (MSB-first, base $E0) and samples stride-8 to the
port's WORLD_COLS (256) lap, and points both `composeFrame` (scene.ts) and
`composeStaticFrame` at it — one decoder, no divergence. `blitTerrain`'s cylinder-fill was made
explicit (an optional `period` opts into full-width tiling) so the still and the scroll stay
distinguishable once the surface length equals WORLD_COLS. The df5-9 seamless-wrap invariant
and the period (WORLD_COLS, once per lap) are unchanged and correct. Corrects ADR-0006's
inferred "$8000/twice per lap" math, verified from the draw path. Does NOT touch the df3
$100/px world scale (a separate un-storied deviation per ADR-0006).
