# Epic sw11 Context

## Title
Star Wars trench — restore authentic return-fire lethality and seat the wall guns flush

## Overview
Follow-up epic from the sw10 native-basis migration (archived). sw10-1/2/3 unified the trench onto the ROM-native world basis, which as a SIDE EFFECT made the wall guns' return fire connect for the first time: before sw10, trenchGunFireVelocity computed its lead on a depth axis (index 2) that disagreed with the gun positions, ship point and swept-collision (all since moved to index 0), so every base-gun shot flew off-axis and MISSED — the trench was accidentally survivable. With the basis unified the fire is functional, and the trench is now unplayable (~3 s to burn all 6 shields). Root cause is NOT a constant over-tune — every difficulty constant is ROM-cited and faithful (TGPROB cadence/threshold WSBASE.MAC:1224, range #6000, 0.5 s shield debounce S-016, 6 starting shields, gun density from the ROM pie tables). The defect is a MECHANISM divergence in the DOBASE/BSGUN/PANLIN/MOVPL port, on THREE independent axes (all detailed in sw11-1), the largest being AIM: the cabinet never leads the ship — it sprays a random-angle shell that heat-seeks weakly and often misses; our port fires a perfect analytic lead that never misses. REFERENCE AUTHORITY: the 1983 assembler source (~/Projects/star-wars-1983-source-text, WSBASE.MAC + WSGUNS.MAC) is the sole authority for this logic. MAME's starwars driver (~/Projects/mame/src/mame/atari/starwars.cpp) is hardware emulation only — matrix processor, math box, AVG vector PROM — that EXECUTES the real 6809 game ROM; it does not reimplement the trench gun logic (grep for trench/bunker/BSGUN in src/mame/atari/ returns nothing), so it corroborates only the coordinate scale we already port and adds no fire-mechanism detail. sw11-2 fixes the visual half of the same sw10 orient retirement: the wall guns render cantilevered off the wall because TRENCH_ORIENT was retired to IDENTITY and no per-wall seating/mirror replaced it.
