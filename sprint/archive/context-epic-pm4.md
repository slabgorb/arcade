## Title
Pac-Man — cabinet lifecycle (attract + state machine + freeze pauses) + fidelity/accessibility fixes

## Overview
Pac-Man equivalent of missile-command mc6 (attract + MAINLINE state machine) plus four reported fidelity/accessibility fixes; the mc7 half (high-score ladder + name entry) is already ported in game.ts, only the attract-screen ladder display + default table remain (folded into pm4-6). Extends core GamePhase from playing|game-over to a pure, seeded, clock-free MAINLINE dispatch keyed on ROM master-state byte #4e00 (pacman.asm:0195 dispatch, :0984/:269a/:318c writes): attract -> ready -> playing -> (dying -> ready | game-over); playing -> level-clear -> ready; game-over -> attract. DELIBERATE deviations from the mc6 template, both recorded in the design: NO pause phase (Pac-Man cabinets have none, not requested) and level-clear FREEZES WITHOUT FLASHING — the boss has photosensitive epilepsy, so accessibility overrides ROM fidelity here (the current full-screen white strobe is a seizure hazard AND non-authentic). Per the arcade fidelity contract, every new src/core constant carries a citations.test.ts-gated claim and purity.test.ts stays green (attract timers + auto-player are frame counts + seeded RNG, never a clock). Design: docs/superpowers/specs/2026-08-09-pac-man-cabinet-lifecycle-design.md. OUT OF SCOPE: pause phase, coin/credit economy UI, intermission cutscenes, maze row-table changes beyond a genuine authoring bug proven by pm4-10.
