# Epic mc8 Context

## Title
Missile Command — authentic audio (W3SOUN + POKEY)

## Overview
Eighth Missile Command epic — the cabinet is silent today (there is no audio module at all in plugins/missile-command/src/shell). This epic gives it the real POKEY voice. The sound-control ROM is already vendored and decoded: A35820.1C is W3SOUN, the WW3 POKEY sound-system control ROM, and it is ASCII ASSEMBLER SOURCE, not an opaque image (docs/rom-study/brief.md O-1 RESOLVED; header '.TITLE W3SOUN-(WAS T2SOUN)', POKEY content AUDCTL/AUDF1). So this is a lift-and-port, NOT a sound-board emulation — the exact pattern star-wars used for speech: read the sound-command tables from the source and drive a POKEY core in JS. Reuse before building (contract 4): @shared/audio, @shared/synth, and the already-vendored plugins/star-wars/tools/pokey-bake/vendor/pokey.js. Executes the Architect roadmap slice for mc8 in docs/superpowers/specs/2026-08-07-missile-command-full-cabinet-roadmap.md; mc8 may begin any time after mc3 since it layers on events the core already emits. May begin in parallel with mc4/mc9. The core/shell boundary holds (contract 2): sound lives in src/shell; if the core must surface game events for the shell to voice, they are pure data on GameState, never a callback or a clock read. ASSETS ARE VERIFIED LIVE, NOT ASSUMED (contract 5 + the sidecar gotcha): @shared/audio degrades SILENTLY at every failure path, so a green vitest is not proof of sound — a 404 is indistinguishable from working code. If any sound is baked to a file, it is uploaded to the R2 bucket 'arcade' (there is NO automated upload path — CI deploys each app's dist/ only) and proven with a live 200, and any 'asset follows later' finding is filed as a story BEFORE the epic finishes. Primary anchors: A35820.1C decodes to W3SOUN (brief.md, PROVENANCE.md); reuse star-wars/tools/pokey-bake. OUT OF SCOPE: the visual work of mc4/mc9.
