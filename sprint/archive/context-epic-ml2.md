## Title
Millipede — graphics-ROM decode (phase 3): picture EPROMs -> baked stamp data + the RAM-colour seam, pixels on screen before physics

## Overview
Second Millipede epic, phase 3 of the raster build (docs/playbooks/next-sprite-game.md). Gets stamps on screen before any game logic, de-risking the coordinate/rotation traps early. Mirrors pac-man's pure gfx-rom.ts + tools/bake-graphics.mjs seam (plugins/pac-man/src/shell/gfx-rom.ts) and centipede's CENPIC 2-bit-planar decode, kept a separate epic from ml1 because Millipede's colour path genuinely diverges. THE NOVEL PART: Millipede colours from COLOR RAM at runtime (millipede/MLIRQ.MAC:242 CLRCH - COLOR RAM INITIALIZATION), NOT a resistor-DAC colour PROM — the 368X1.DOC ledger lists no colour/sync PROM (only 4 program + 2 picture EPROMs). Design the palette source off MAME milliped.cpp, not centipede's SYNC.MAC 82S129 model. Picture pixels come from the MAME milliped set 136013-106/107 (368XX.SB2 was not preserved upstream — ml1 OQ-3). Bake, don't fetch: ROM bytes -> committed *-data.ts, decoded output in-tree and diffable while the reference bytes stay licence-walled. Dependency: ml2 -> ml1 (needs the citation gate + brief). Every new src/core constant carries a claim gated by citations.test.ts; MAME cited in prose, never copied (GPL). Design: docs/superpowers/specs/2026-08-11-millipede-cabinet-roadmap-and-ml1-design.md (section 4, ml2). OUT OF SCOPE: game logic (ml3+), sound (ml6), attract/HUD (ml7).
